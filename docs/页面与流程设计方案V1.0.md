# 新能源场站运行管理——页面与流程设计方案 V1.0

状态：设计评审稿。依据：《需求基线V1.0-已确认》及五轮确认记录。**本交付为信息架构、页面结构、交互规则和静态线框，不是可运行演示系统；本轮不修改已发布站点。**

## 1. 设计目标

让调度能找到该派的任务，让现场能明确当前作业和未完成前提，让审批与验收人员能依据证据处理，让站长能追溯到班次、设备和关联票据。以业务对象分别管理状态，跨对象建立关联，避免一个事件状态代替缺陷、工单和票据。

与原型保持功能对应，但重新组织导航和信息层级。原型的页面说明、弹窗示例、流程图不直接平铺为业务菜单；原型四类工作票的字段差异、三类工单的执行差异均保留。

## 2. 信息架构

### 2.1 全局框架

- 顶栏：业务域、场站范围、演示业务日期/时间、业务视角、消息。视角用于突出待办，用户仍可查看全站内容，不引入权限系统。
- 左侧：九个一级模块；当前模块展开二级菜单，面包屑显示当前位置。
- 内容区：标题和主操作、视图/筛选、业务主体。详情使用统一身份区和各对象自己的业务页签。
- 右侧抽屉：选设备/人员/来源单据/危险点、派发、过程登记、物料登记。复杂编制采用整页，不把长票据塞进小弹窗。
- 底部或页头固定操作区：最多一个当前阶段主操作，次要操作与作废分开。不可执行操作显示具体缺失条件和跳转入口。
- 全局消息可定位到具体对象和未完成环节；演示时间推进和重置放在演示工具入口，不占据每张业务表单。

### 2.2 菜单分组

| 一级模块 | 二级内容 | 组织理由 |
|---|---|---|
| 工作台 | 我的待办、全站关注、演示场景入口 | 用任务导航进入业务，不用大图遮盖待办 |
| 感知预警 | 设备监测、异常事件、研判详情 | 区分测点、预警事件和缺陷 |
| 缺陷管理 | 缺陷台账、缺陷审批、人工报障 | 审批退回与消缺处置进度分别展示 |
| 任务工单 | 工单总表、待分配、已挂起、消缺验收 | 三类工单共用入口，详情结构分别设计；验收只列消缺 |
| 票据中心 | 工作票、操作票、工作票待办、操作票待办 | 四类工作票与操作票采用不同模板和过程 |
| 值班日志 | 当前日志、日志查询、值班日历、排班管理 | 排班、当前班次、交接内容相邻，便于追溯 |
| 通知命令 | 通知交代、调度命令 | 通知阅读与命令执行/回令不混用 |
| 任务计划 | 定检规则、巡检线路 | 规则与其生成的工单分开，避免把编辑规则当成编辑历史任务 |
| 基础配置 | 工作票危险点、操作票危险点、固定审批流程、年度职责人员、业务指引 | 保留两类库及固定流程，只维护原型允许维护的业务内容 |

## 3. 列表与详情的共用交互

### 3.1 列表

- 顶部视图表达业务分组，筛选表达条件，两者不替代真实对象状态。示例“我的待办”不是“审批中”状态。
- 表格首列显示业务标题和编号；保留来源、场站、设备、类型、状态、负责人、计划/实际时间和操作。
- 超时独立标识，挂起不移除超时；“已退回”可见原因摘要和待补内容。
- 点击标题进入详情。批量动作仅放在明确同阶段可执行的列表，不在设计中加入原型没有依据的批量签发/许可。
- 空列表说明是筛选无结果还是尚无数据；未分配显示“待分配”，不以空白掩盖责任缺失。

### 3.2 详情

身份区始终显示对象名称/编号、场站设备、状态、当前负责人及相关期限；流程条只表示本对象流程。

页签为业务信息、执行/处置、关联单据、物料（工单适用）、附件、记录。具体页签数量按对象调整；原型已有内容不被统一布局删掉。

跨对象关联展示“对象类型＋编号＋当前状态＋查看”，记录当前关联用途。票据终结条件列出本次作业需执行的票据，而不是所有曾被引用的历史文件。

主动作旁显示未满足条件。例如“验收通过”不可用时，同时展示未终结票号和进入票据详情的入口，不能只显示灰色按钮。

退回、作废、挂起、改派各自有原因及处理记录。所有终态对象进入只读记录，可查看历史，不用删除模拟“关闭”。

## 4. 核心页面与表单结构

### 4.1 工作台 A01

核心为按当前视角聚焦的待办，不以装机容量、发电量等未定义经营指标占主区域。

| 区域 | 内容 | 点击去向 |
|---|---|---|
| 视角切换 | 调度、现场、站长/值长、签发/许可职责 | 切换待办聚焦，不改变对象状态或授予权限 |
| 主待办 | 待研判、待审批、待派发、待执行、待签发/确认/许可、待验收 | 对应列表或处理页面 |
| 关注区 | 缺班任务、超时、票据阻断验收、交代待补 | 对应待处理对象及缺失说明 |
| 当前班次 | 起止时间、跨日标志、负责人、班前交代 | 当前日志 |
| 全站追踪 | 事件/缺陷/工单/票据编号可串联 | 对象详情及关联页签 |

### 4.2 研判 A04 与缺陷 D02/D05

研判页左区展示设备测点、单位、采样时间和趋势；中区展示异常规则/聚合次数、首次末次时间、同类采样记录；右区填写研判依据，主操作为“确认并登记缺陷”，次操作为“排除异常”。

研判确认先打开缺陷表单，带入设备、来源事件和证据；提交缺陷审批成功后，事件才显示已转缺陷并链接缺陷编号。不能点击研判确认就直接派工。

缺陷表单：场站、设备、来源、来源编号、缺陷类别、描述、照片。来源自动带入不可改写为其他链路；人工报障不显示强制来源工单。退回补充模式突出退回理由，保留同一缺陷编号和历次提交。

审批页显示原始描述与本次修改、照片及来源；处理人输入审核意见，通过生成待派发消缺工单，退回要求填写补充要求。作废独立放在更多操作，并受已采纳的下游执行限制。

### 4.3 工单 O01–O05

| 页面 | 主体结构 | 主操作 / 完成条件 |
|---|---|---|
| 消缺O02 | 缺陷快照、派发方案、现场原因与处置、复测/恢复证据、票据、物料、历史 | 接单→核验许可后开工→提交验收；挂起/恢复/改派有记录 |
| 定检O03 | 规则快照、工作内容、逐设备工作项及结果、异常缺陷关联、票据物料 | 执行必做项→负责人完成；关联作业票终结，不要求所有新缺陷先消除 |
| 巡检O04 | 左侧巡检点导航，中区设备与记录/观察项，右侧本点进度/异常 | 每项录入与保存→点完成→负责人完成全单；异常直接登记关联缺陷 |
| 验收O05 | 处置前后信息、原因措施、照片/记录、票据终结清单、验收历史 | 填写结论通过或退回；未终结作业票阻断通过，但不阻断查看、填写或退回 |

派发抽屉包括推荐班组、负责人、推荐依据、当前在办任务摘要、替换选择、计划完成时间和派发说明。推荐依据为可解释的演示规则（设备技能、场站、在办负荷），不展示未经定义的算法评分。

缺班补派抽屉保留原计划时刻和来源规则，不重建一张工单；改派未开工任务与执行中移交使用不同标题，执行中保留已完成项、照片和记录。

物料抽屉使用编号、名称、数量、单位、单价、金额、领用日期；金额自动计算。物料仅做登记，不出现采购单、库存扣减和财务审批入口。

### 4.4 工作票 T02/T03/T05

整页编制采用纵向分节与固定章节导航。先选择票种，再呈现对应结构；票种变化导致字段清空时在设计中保留明确提示，不静默丢失内容。

| 章节 | 公共内容 | 差异内容 |
|---|---|---|
| 基础与关联 | 设备、工作内容、负责人、成员、计划起止、工单/命令/通知关联 | 联系单显示其票种名称，不显示两次许可 |
| 安全措施 | 可增删措施行，内容与执行记录分别保存 | 一种：断开/接地/标识围栏/检修措施；二种：工作条件/安全注意事项/标识等；风机：运行与检修、机械隔离、接地；联系单不复制三类措施分组 |
| 危险点 | 从工作票库选取编号、分析、预控措施，保存快照 | 联系单保留危险点执行情况 |
| 流程 | 编制、签发、负责人确认、许可人许可、执行、终结 | 联系单仅签发、执行、终结 |
| 过程登记 | 按适用票种登记人员变更、延期、试运行、恢复和措施执行 | 风机细分运行/检修措施及挂牌上锁，试运申请与恢复记录；不额外发明审批链 |
| 终结 | 工作结束、现场恢复清理、终结时间、附件 | 按原型适用字段录入接地线组数、接地刀闸数等，不强迫联系单填同样字段 |

签发处理区填写批准工作时间，默认计划时间并可调整；工作负责人确认和许可人许可各显示本节点责任、相关措施与填写区，分别记录人和时间。任何节点退回编制人后，当前版本正式打印不可用，修改重提新版本重新签发。

正式PDF按钮按D02门槛显示；草稿预览显示“草稿”标识，带明确版本。历史已签发版本留在版本记录，不与当前退回版本混用。

### 4.5 操作票 T07/T08/T10

- 顶部：一级/二级类型和模板说明；右侧显示模板为演示示例及版本，不把未定项目标成正式规程。
- 人员：发令人（班次负责人）、受令人/监护人、操作人（当前提交人，原型不可修改）、起止时间、操作类型。
- 操作任务：设备与任务描述；顺序项目表显示序号、项目、执行记录、完成时间。示例13项仅用于对应模板，不强制所有类型都是13项。
- 危险点：使用操作票专有的危险点、后果和控制措施，不混用工作票库。
- 签发处理核查任务、项目、人员和危险点；通过后可正式打印，退回编制人修改后重走签发。
- 执行页逐项记录并显示未完成项；结束后填写终结信息、监护人、附件。六类分类和状态转换按原型表保留，缺少的具体项目以可编辑演示模板表达；电气刀闸范围保持基线约定。

### 4.6 任务规则 R02/R04

定检编制：基础信息→设备工作项→时间交集→触发预览。巡检编制：线路基础→巡检点树→点下设备与巡检项→时间交集→触发预览。

时间区不直接展示难懂的表达式：月份、月内周次、星期、日号、多个时点分组，组合摘要为“所选条件共同满足时触发”；右侧列未来触发时刻、计划负责人、预计完成时刻。空交集和无效日期在预览中解释，无排班显示将进入待分配池。

记录项显示数值/文本、单位及本次结果；观察项显示观察内容与正常/异常记录。具体设备阈值作为演示配置，不借用上一版75℃通用于所有设备。

### 4.7 排班 L05 与当前日志 L01

排班以月历为主体，选中日期后右侧展示该日及跨日班次详情；跨日班标签为“20:00—次日08:00”，班次归属日以开始日展示，实际事件归属以时间区间判定。

批量设置抽屉先设置日期、班次和有序人员，再预览轮排结果，冲突行不可悄悄覆盖；休假调班显示调整前后对照和最后一班补回人员；单日修改显示受影响的未来任务提示，不修改历史执行记录。

当前日志身份区显示实际起止、人员及“值班中/已交班”和“交代已填/待补”两类状态。班前交代为前班只读引用；业务事件按时间倒序，带编号可查看。班后交代可在班后补填，保留补填时间并更新后班引用，不覆盖后班独立记事。

### 4.8 通知、命令与配置

通知新增采用简短抽屉：收令人、内容，发令人及时间显示；提交后系统消息链接到通知详情。无原型依据的已读回执不作为新审批节点。

调度命令详情分得令信息、执行、回令三段，当前阶段只突出一个主操作。执行后保留执行人时间并进入待回令，回令后只读归档，不等同于工单验收。

两类危险点库使用相似列表外观但不同业务字段。年度职责导入采用上传/粘贴模板数据→预览校验→确认导入三步，失败行说明年份、场站、职责或人员匹配问题，固定审批流程只读。模板及导入规则为演示数据处理，不隐含生产人员授权。

## 5. 跨对象关键流程

### 5.1 消缺主线

测点产生异常→异常事件待研判→确认登记缺陷→缺陷审批→待派发消缺工单→系统推荐、调度确认→接单→按关联作业要求核验许可→处置记录→提交验收→核查作业票据终结→站长/值长通过→工单已关闭、缺陷已消缺。

异常事件保留来源和处理记录，不用工单关闭去伪造真实告警复归；设备采样恢复与业务闭环分别展示。

### 5.2 定检/巡检支线

规则时间交集命中→唯一生成任务→找到当班负责人则待执行；找不到则待分配提醒调度→执行设备工作项或巡检项→异常登记为待审批缺陷→本任务必做项完成且作业票终结→负责人完成。关联缺陷继续独立消缺，不给定检/巡检增设站长验收。

### 5.3 票据支线

工作票三类：编制→签发→负责人确认→许可人许可→执行与正式打印→过程登记→终结补录及附件。联系单/操作票：编制→签发→执行与正式打印→终结；操作票另含草稿和逐项执行。

退回均回编制，修改版本从签发重走；作废为单独操作，不代替已执行作业的票据终结。

### 5.4 交接与缺班

到达排班结束时刻→上一班自动交班、下一排班生效→交代缺失标记待补并提醒→补填后保留补填时间并同步引用。跨日连续班次不在零点拆开。无下一排班不是“继续沿用上一负责人”，定时任务生成待分配工单。

## 6. 关键动作条件与异常反馈

| 动作 | 可执行条件 | 条件不满足时的呈现 |
|---|---|---|
| 预警转缺陷 | 研判依据及缺陷必要字段完整，未重复转单 | 显示已关联缺陷链接，避免重复生成 |
| 缺陷审批通过 | 当前为待审批，本次资料完整 | 已退回显示补充入口，不提供再次通过造成重复工单 |
| 消缺开工 | 已接单、需许可的关联作业已完成对应许可 | 列出待负责人确认或待许可人许可票据及处理入口 |
| 三类工作票正式打印 | 当前版本已完成签发和两次确认 | 提供草稿预览，说明当前停在哪个节点 |
| 联系单/操作票正式打印 | 当前版本已签发 | 未签发只能带草稿标识预览 |
| 消缺验收通过 | 处置证据与结论完整，作业票据全部终结 | 明确票号、状态和待完成事项；仍可退回处置 |
| 定检/巡检完成 | 必做项有结果，异常已登记，关联作业票终结 | 定位未完成的设备/巡检点/项目或票据，不要求新缺陷先消除 |
| 挂起 | 当前执行阶段，填写原因 | 显示原期限与超时，不自动改期 |
| 作废 | 符合基线下游执行约束且说明原因 | 有下游执行时展示关联记录，不能一键把链路当作已完成 |
| 规则触发 | 规则在用，命中交集且此计划时点未生成 | 空交集提示、停用不生成、重复时显示已有任务 |

## 7. 视觉和静态线框规范

本轮提供12张代表页面静态线框，使用统一的企业作业系统布局：深色窄导航、浅色内容区、蓝色主动作、明确的表格和流程状态；重心是信息密度、字段分组和处理条件，不以大幅宣传式标题或装饰性图表占屏。

- 桌面基准画布1600×1000；列表正文约14–16px，章节16–20px；真实开发阶段再验证常用桌面尺寸和缩放。
- 状态文字配合色点/标签，不只靠颜色；退回、挂起、超时、待补、未分配各有可读名称。
- 线框的按钮、输入框和页签为静态示意，不具有提交/派发/许可功能；线框样例数据用于解释布局，不代表实际数据已创建。
- 页面中展示的模拟测点/设备参数均标注演示信息，具体值和模板内容在数据设计阶段确定。

## 8. 设计评审与后续范围

本轮可评审：九模块导航是否符合工作习惯；三类工单详情及长票据分节是否易用；审批/处置/验收是否有清晰的当前动作；跨班次追溯与票据阻断提示是否可理解。

尚未开展：业务程序开发、数据库/API实现、真实设备或外部通知接入、发布站点、可交互端到端测试。下一步只有在用户明确进入开发后，才按基线与设计准备可运行版本，并按T01–T14完成验证。
