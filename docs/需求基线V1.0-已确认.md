**状态：已整体确认，已授权进入页面与流程重新设计；暂不开发。** 整理日期：2026-11-02。

来源：墨刀《运行管理》全部45个实际页面，以及五轮业务确认的15项选择。本文合并最新结论，不再沿用首个演示版对功能范围的缩减。逐页字段详情见《原型需求梳理V0.1》，事实查证见《原型45页阅读清单与摘录》，确认历史见《需求确认记录》。

## 1. 产品目标与范围

【已确认】开发可供领导演示的完整场站运行管理测试版本，保留原型所有模块与票种，并补感知预警和消缺验收。以光伏逆变器异常为主要讲解案例，电脑端切换业务视角。

功能范围包括日志与交接班、排班、定检规则、巡检线路及项目、缺陷审批、四类工作票、操作票、通知交代、调度命令、三类工单、两类危险点预控库、固定审批流程、年度职责人员；加上原型缺少的异常研判、人工报障和消缺验收。

原型中的分布式能源、户用储能、能碳管理目前仅有业务域切换入口，没有各域完整需求。保留入口不等于已定义其全部业务。风机工作票在本次完整功能范围内，不因主案例为光伏而删除。

## 5. 模块需求的执行基线

### 5.1 排班与日志

【原型】按未来日期范围、班次时间和有序负责人列表循环轮排；支持单日调整；休假将范围内后续班次向前挪，最后一班安排休假人。日志按实际班次时间倒序聚合值班记事、缺陷、票据、调度命令、通知交代。

【已确认】跨日不在零点拆断。到点自动进入下一排班，未填交代不阻塞交班。前班交代继承到后班。

【已采纳默认】班次时间区间采用“包含开始、不包含结束”，交接时刻只归下一班；缺失交代先显示待补，补填后保留补填时间并同步后班只读引用；不覆盖下一班自己已写的内容。重叠排班先提示冲突，不自动随机选人。

### 5.2 定检与巡检

【原型】月、月内周次、星期、日号和多个时间取交集；在用规则到点生成工单，负责人取当期排班；停用仅停止后续触发。定检含设备和工作内容，巡检含巡检点、设备、记录/观察项。计划完成天数用于计算期限。

【已确认】无当班负责人时也生成工单，进入待分配池。定检/巡检无需独立验收，负责人提交完成。

【已采纳默认】同规则同计划触发时间只生成一次；预览未来触发时间和接收人以解释交集；计划完成天数按触发时刻起算自然日。已生成任务保留规则快照。完成时检查必做项有结果；发现的缺陷独立跟踪，不要求所有缺陷消除后才能完成原巡检/定检。

### 5.3 缺陷、消缺与验收

【已确认】来源五类：定检、巡检、预警、告警、人工报障。前四类保留来源关联，人工报障不强制来源工单。预警/告警研判确认后先待审批，审批通过后生成待派发消缺工单。退回补充再审，作废另设。

【已确认】系统推荐班组及负责人，调度确认派发；站长/值长验收。处置可先提交，关联作业票据未全部终结不得验收通过。验收退回继续处置，通过才关闭消缺工单和缺陷。

【已采纳默认】缺陷在验收前保持待消缺，另显示关联工单的处置/待验收进度；通过后变已消缺。保存处置提交、执行结束、票据终结、验收通过等独立时间，避免一个“结束时间”覆盖所有业务含义。

### 5.4 工作票与操作票

【原型】四类工作票保留各自安全措施字段及危险点引用。操作票保留一级/二级类型、操作类型、人员、顺序项目、危险点与关联单据。三类工作票不能只共用表单换标题。

【已确认】三类工作票经过签发→工作负责人确认→工作许可人许可。任一步退回编制人后重新走签发，旧记录保留。联系单和操作票按各自签发流程，无上述两次确认。

【已确认】三类工作票正式打印须完成两次确认，联系单和操作票须完成签发。草稿带标识预览。执行过程中登记变更、延期、试运行和操作项目结果，结束后补录终结及附件。

【已采纳默认】每次修改重提形成新版本，已通过记录仅对应原版本；正式输出 PDF 显示票号、版本、当前流程及人员时间。危险点库引用保存快照，改库不改历史票。变更/延期/试运行先实现过程记录，不擅自新增用户未定义的审批链。

### 5.5 通知、命令与配置

【原型】通知交代新增后通知收令人；调度命令新增通知执行人，待操作→待回令→已结束。两类危险点库分别维护。年度职责导入字段为年份、场站、职责类型、姓名。审批流程固定只读。

【已采纳默认】演示通知集中在系统消息中心，不发送真实短信或外部消息；职责导入先预览并反馈重复/错误行，再确认写入演示数据。权限虽不实现，业务节点仍明确记录实际选定的处理人。

## 6. 状态流转与联动表

以下“流转方向”为已确认或原型明确的业务路径；**具体状态名称按本表作为设计统一用语，已整体采纳**。不会再把异常、缺陷、工单和票据合成一个状态字段。

| 对象 | 建议状态与流转 | 关键动作与约束 |
|---|---|---|
| 异常事件 | 待研判→已转缺陷；待研判→已排除 | 转缺陷先待审批；排除理由与重复聚合采用S03，不把验收关闭当成真实设备告警复归 |
| 缺陷 | 待审批→已退回→待审批；通过→待消缺；验收通过→已消缺；另有已作废 | 退回不生成工单；审批通过幂等生成消缺任务；有下游执行后不能无说明作废 |
| 定检/巡检工单 | 自动派发→待执行→执行中→已完成；缺班时待分配→补派→待执行 | 负责人提交完成，无待验收状态。接单与挂起采用S01、S02 |
| 消缺工单 | 待派发→待接单→待开工→处置中→待验收→已关闭；验收退回→处置中 | 派发、处置、验收主链已确认；接单和待开工按S01细分。需要许可的作业许可齐备才开工，沿用先前确认 |
| 三类工作票 | 编制→待签发→待负责人确认→待许可人许可→执行中→已终结 | 任一步退回→已退回→修改重走签发；另设已作废。“执行中”对应原型“待终结”的业务阶段，不再混用为两个独立顺序节点 |
| 工作联系单 | 编制→待签发→执行中→已终结 | 签发后正式打印；退回和作废分别记录，无许可链 |
| 操作票 | 草稿→待签发→执行中→已终结 | 签发后正式打印；随过程登记逐项执行及时间；退回编制后重走签发 |
| 调度命令 | 待操作→待回令→已结束 | 操作完成记录执行人/时间；回令完成记录回令人/时间 |
| 规则 | 在用↔停用 | 不影响历史任务；编辑生效及演示触发在设计中细化 |
| 班次日志 | 班内记录→到点交班→已交班/交代待补→交代已补 | 交班状态与交代填写状态分开，防止待补造成班次不切换 |

三类“退回”必须区分：缺陷审批退回到补充资料；票据退回到编制并重走签发；消缺验收退回到现场处置。各自记录原因、操作人、时间和重提历史。

|---|---|---|
| S01 工单接单与改派 | 消缺派发后接单，再核验开工条件；定检/巡检可直接开始执行。未开工可改派；开工后变更负责人保留移交记录，不清空已有结果 | 工单中间节点和责任追溯 |
| S02 挂起恢复 | 执行中可因待备件/天气/外协等挂起，记录原因，恢复回原执行阶段；保留原期限，延期另记，不静默抹掉超时 | 保留P01挂起功能，避免挂起成为终态 |
| S03 预警去重与排除 | 同设备、同规则、同一未结束异常过程聚合次数及最新采样，不重复转缺陷；人工排除需依据。归档后再次出现异常另开事件 | 预警中心与来源追溯；具体时间窗和恢复判据为演示参数 |
| S04 作废范围 | 缺陷未产生下游执行时可作废并说明原因；已开始作业不一键作废整条链，单独处理相关票据和工单；作废票据不自动视为工作已完成 | 防止通过作废绕过票据终结校验；复杂撤销流程暂不扩展 |
| S05 定检/巡检完成约束 | 必做设备/巡检项有结果，相关异常已登记；如关联了本次需执行的作业票，票据也应终结后再完成。缺陷可后续独立消缺 | 已随整体基线采纳，也适用于定检和巡检 |
| S06 时间和规则边界 | 按起止时刻唯一归班；重叠排班提示冲突；第一周/最后一周按月历自然周与本月相交计算；无效日跳过、空交集提示；触发预览解释生成结果 | 时间算法为建议，不是已确认排班制度 |
| S07 操作票模板 | 分类表明确的六类均保留；先用原型已有运行转检修项目及字段构建可编辑演示模板。其余转换项目须由产品/业务确认，标明演示模板；“电气刀闸”因仅有筛选示例，暂保留待定范围 | 不把未知项目编成正式操作规程，也不宣称所有票种项目已定稿 |
| S08 物料及记录 | 保留编号、名称、数量、单位、单价、金额、领用日；金额自动计算。仅登记领用，不引入采购、库存扣减及财务审批。操作、审批、附件均关联具体业务对象 | 覆盖原型物料功能，避免扩大成物资系统 |
| S09 演示技术边界 | 模拟测点、虚构数据、可重置与导出；时钟推进用于定时任务及交接班演示。存储方式另作技术方案，不默认继续使用上一版本机localStorage | 需求基线不提前锁死技术实现；需保障一次完整演示持续可用 |

若需真实设备接入、实际安全判据或生产操作规程，应另有设备资料和场站制度作为需求依据；本次不以模拟阈值替代这些资料。

## 8. 演示数据与验收场景

本表为已采纳的演示验收清单，后续经设计评审并获准开发后作为检查依据。测试数据覆盖所有模块，不再仅准备几张消缺工单。

| 场景 | 应演示的结果 |
|---|---|
| T01 完整异常消缺 | 测点异常→研判→缺陷审批→推荐派发→票据签发与双确认→处置→提交验收→票据终结→验收关闭 |
| T02 审批退回重提 | 缺陷退回修改重提；票据任一确认节点退回后重走签发；原版本和退回理由可查 |
| T03 验收前票据未终结 | 可以提交验收；票据未终结时通过按钮受限并指出未完成票据；终结后可通过 |
| T04 验收退回 | 消缺恢复条件不足，站长/值长退回；现场补充结果重提；历史保留 |
| T05 定检规则 | 配置设备、月份周日时间交集和期限；预览/触发生成任务；当班负责人执行并完成，无验收环节 |
| T06 巡检线路 | 多巡检点、各点设备和记录/观察项；逐项提交结果；发现异常创建关联缺陷，原巡检任务完成 |
| T07 缺班补派 | 规则到点但无负责人，生成待分配任务并通知调度；补派后保留原计划和来源 |
| T08 排班交接 | 批量轮排、休假顺延、单日修改；跨零点不拆班；到点自动交班，交代待补并可补填 |
| T09 班次日志 | 票据、缺陷、命令、通知与记事落入正确班次，倒序查看，前后交代可追溯 |
| T10 四类工作票 | 对照各自安全措施字段；展示两次确认或联系单签发；草稿水印/正式PDF；变更延期试运及终结附件 |
| T11 操作票 | 草稿、分类与项目、危险点引用、签发退回重提、逐项执行、正式打印和终结补录 |
| T12 调度命令与通知 | 通知送达演示消息中心；命令操作完成后待回令，回令后已结束；日志可追溯 |
| T13 配置引用 | 两类危险点库可编辑并被各自票据选择；职责人员模板导入及错误反馈；审批流程只读 |
| T14 异常分支 | 重复预警、误报排除、人工报障、独立作废、挂起恢复、改派和超时，按S项审阅结论实现 |

建议数据包至少含：3座虚构场站；跨日/正常/缺失排班；定检和巡检多条规则；多点多设备线路；五类来源缺陷；三类工单各状态；四类工作票各阶段与退回版本；操作票草稿、执行、终结记录；未终结票据阻断验收样例；两类危险点条目；年度职责及导入成功/错误样例；物料、附件、通知和回令记录。具体条数在数据准备阶段按覆盖矩阵确定，不先用数量替代功能覆盖。
