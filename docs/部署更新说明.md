# 部署、更新与数据保存

## 外置运行结构

从0.2.2起，发布包为标准可执行JAR，Manifest主类为NeomsApplication，Class-Path自动引用lib下的运行时依赖。Windows、Linux、macOS统一使用`java -jar neoms.jar`，不再需要loader.properties或任何loader参数。JAR不嵌入第三方依赖、Vue文件或Spring配置。依赖由Maven runtime范围复制到lib，应用自动以JAR目录定位config、config/static、logs和data/uploads，即使从其他目录使用完整JAR路径启动也有效。运行环境需要Java21及可连接的MySQL；数据库连接信息仍只需在config/application-local.yml配置一次。

数据库初始需要独立 `neoms_demo`，字符集utf8mb4。应用启动自动建立 neoms_records、neoms_history、neoms_users、neoms_files 四表，应用账号需该库建表、查询及写入权限。不会替用户创建或删除其他库。首次启动时仅在业务表为空的情况下初始化数据；再次启动不覆盖已有数据。

本机地址localhost:3306连接已验证。通用包不包含真实密码；在config/application-local.yml填写，或通过环境变量NEOMS_DB_PASSWORD传入。自定义端口用NEOMS_PORT；也可在外置配置改server.port。前端接口同源，不需要额外Web服务或Node运行时。

## Windows

前台：start.cmd 或 powershell -File start.ps1。后台：powershell -File start.ps1 -Background。后台会生成neoms.pid、logs/console.log及console-error.log，stop.ps1会核对PID对应Java与neoms.jar后停止。应用日志logs/neoms.log。前台Ctrl+C正常关闭。

Windows临时目录兼容处理由应用内部完成，无需额外JVM参数。若端口占用，使用另一个端口或先关闭本项目已有实例，脚本不会自动结束不相关进程。

## Linux / macOS

前台bash start.sh，后台bash start.sh --background，停止bash stop.sh。macOS另提供start-macos.command，可赋执行权限后双击。Java路径优先JAVA_HOME，否则PATH。依赖系统可用Java21+，MySQL可远端连接。此交付在Windows环境实机验证；Linux/macOS脚本提供并作静态检查，未在这两种系统实机运行。

## 局部更新

1. 备份数据库、当前业务JAR、config目录与data/uploads，记录lib清单。停止本项目应用。
2. 仅后端业务变动：替换neoms.jar。本版业务包约百KB级，依赖不需重新复制。
3. 仅前端变动：将旧config/static改名备份，再放入新的完整static目录，避免引用过期文件；数据库及业务JAR无需改变。
4. 依赖变动：对比lib-manifest.sha256，替换变动JAR，移走同一artifact旧版本，保留未变依赖。不能只叠加不同版本。需要新增依赖时可以局部补充。
5. 配置调整合并到现有文件，不直接覆盖本地密码配置。启动后访问/api/health并登录，验证一个查询和附件打开。

数据库结构变动、业务字段迁移应随以后版本给迁移说明。0.1.0不提供热替换、滚动部署、自动备份或通用数据库升级器。

## 数据操作

右上角时钟的重置只重建本项目的虚构业务与操作历史，示例用户保留，附件文件保留，不清理用户数据库和其他目录。导出JSON包含业务对象及当前演示时间，不含数据库登录密码和用户密码散列；导出用于审阅/保存现场结果，暂不提供导入恢复。可通过MySQL备份和附件目录备份恢复完整状态。

初始账号密码仅适用于内网演示。此版本按需求不做完整权限体系，不应直接暴露为生产系统。
